# Physical-device evidence for Apple

Apple requires a real recording of the candidate app on a physical device running the latest available operating system. Browser previews, simulators and generated videos do not satisfy this request.

## Before recording

1. Install the new Valley Estates candidate through TestFlight. Confirm its build number. Do not record an older build and submit a newer untested one.
2. Update the physical iPhone to the latest available iOS. Note the device model and full OS version. The game also supports iPad, so complete a physical iPad QA pass on current iPadOS before submitting.
3. Start a new estate only if you are comfortable losing the existing estate. Reset explicitly deletes the current save and its recovery copies. Normal review does not require erasing progress.
4. Enable screen recording. Do not expose private notifications, Apple ID details, passwords or other apps' sensitive information.

## One continuous recording

Aim for approximately 3 to 5 minutes, longer if needed to show the normal flow clearly. Do not splice simulator footage into it.

1. Begin on the device Home Screen and launch the installed Valley Estates app.
2. Show the initial instructions or normal saved-estate loading. If using a progressed estate, explain that it is an existing local save.
3. Select a farmhand and assign resource gathering. Pan and zoom the estate.
4. Open Build, choose an affordable building, place it and assign construction work.
5. Open the homestead or farmhands/research panel. Show the available features, an affordable study, and its progress. Show that tapping an active study does not spend the cost twice.
6. Show vineyards, winery, livestock and the virtual market if unlocked in the demonstrated estate. No real purchase is needed and there are no account, registration, account-deletion, UGC or paid-content flows to demonstrate.
7. Open Menu. Demonstrate mute and sound levels, text/layout options, and Credits and licences.
8. Return Home briefly, reopen the app and show the estate resumes with its saved progress and responsive controls/audio. Allow the normal autosave to run before leaving.

## Physical QA notes to return

Send the original recording plus:

* Device model, installed OS version, TestFlight build number and test date.
* Whether launch, tapping/dragging/pinching, construction/research, sound controls and background/resume worked without a crash or freeze.
* iPad model/OS and QA results, because iPad is a supported device family.
* Any problem encountered. If a fault is found, fix it and record/test the replacement build before review submission.

The recording can be hosted at a reviewer-accessible link after it is checked. Verify the link works without requesting access or signing into an account. Do not state that physical QA passed until these results are actually available.
